# Repoman — living backlog and lightweight decisions

Single file for **actionable tasks** and short **architecture / product notes**. Treat it like an in-repo issue tracker (not a formal numbered ADR series).

## How we use this file

- Every task is a **Markdown checkbox**: `- [ ]` open, `- [x]` completed. Keep completed items **in the same list** for history (do **not** maintain a separate "Done" section).
- Prefer **one line per task**; add bullets under a task only when needed.
- Do **not** put employer-specific paths, internal codes, or secrets here.

## Workflow (mandatory)

See **[AGENTS.md](AGENTS.md)** → **Product backlog (`.adr.md`)**. Before starting implementation work on a **feature**, **bugfix**, or **non-trivial refactor**, add or refresh an entry here so work stays traceable. Ship the matching `- [x]` update in the same merge series as the code.

Authoritative behaviour and roadmap tables: **[docs/design/repoman.md](docs/design/repoman.md)**.

## Principles / pointers

- **Preview-first**: mutating commands default to preview; `--write` applies persistent changes where the design specifies it.
- **Pure vs. I/O**: planners and layout under `src/repoman/` stay testable without disk/network when feasible; subprocess `git` and HTTP live in runners/clients (`docs/design/repoman.md` §4).
- **Discovery cache**: honour `CI=true` → TTL 0 once caching exists (design §14).
